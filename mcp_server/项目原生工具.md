# 项目原生工具

> AuraBot 安装时幂等写入项目 SQLite 的内置工具。


## Task Agent

### FileSystem

FileSystem 是项目原生 MCP Server 提供给 Task Agent 的基础文件与命令执行 ToolGroup。
AuraBot 将 MCP Server 返回的 Tool `name` 原样暴露给 Agent，不生成别名。

#### 共同约定

- 所有 Tool 使用 MCP `tools/list` 返回的 `name`、`description`、`inputSchema` 和
  `outputSchema`；AuraBot 通过 OpenAI function tool 协议把 `name`、`description` 和
  `inputSchema` 提供给 Agent。
- 本节 `outputSchema` 只描述调用成功时 MCP `structuredContent` 的结构。调用失败时，
  MCP Server 必须返回 `isError = true`，并在文本内容中提供简短错误；可同时返回
  `{"error":{"code":"...","message":"..."}}` 形式的 `structuredContent`，但错误对象不受
  成功输出 Schema 约束。
- 相对路径以当前 Task 的工作目录为基准。绝对路径只能指向 Task 已授权的文件系统范围。
  服务端必须先规范化路径并解析符号链接，再检查权限；符号链接不能用于绕过授权范围。
- 路径中的 `~`、环境变量和 shell 表达式不自动展开。路径参数不是 Bash statement。
- 除 `bash` 外，文本读取和编辑统一使用 UTF-8。二进制文件、无法解码的文本文件返回
  Tool error。
- 文件大小使用 byte；行号和列号从 `1` 开始，`read_file.offset` 除外。
- 返回路径使用规范化绝对路径。目录项和搜索结果按路径、行号、列号稳定排序。
- 文件系统 Tool 不跟随目录符号链接递归遍历。

#### `edit_file`

**MCP Server 返回的 Tool 名称**

```text
edit_file
```

**Tool 功能描述**

```text
原子编辑一个已存在的 UTF-8 文本文件。按 edits 顺序执行精确文本替换；默认要求 old_text 在当时内容中恰好出现一次，replace_all=true 时替换全部出现位置。expected_sha256 可校验 read_file 返回的文件版本，避免覆盖并发修改。任一校验或替换失败时不写入任何内容。
```

`edit_file` 采用精确替换，而非整文件覆盖：

- `edits` 在内存中的中间内容上依次执行，全部成功后才原子替换原文件。
- `replace_all` 省略或为 `false` 时，`old_text` 必须恰好出现一次；出现 `0` 次或多次均
  返回错误。
- `replace_all = true` 时，`old_text` 必须至少出现一次。
- `old_text` 可以为空字符串，但只允许 `edits` 仅有这一项、目标文件为空；
  `new_text` 将成为文件全部内容。此规则用于写入 `create_file` 创建的空文件。
- `new_text` 可以为空字符串，表示删除匹配内容。
- 提供 `expected_sha256` 时，服务端必须在修改前验证当前文件哈希；不一致时返回冲突，
  Agent 应重新调用 `read_file`，不能盲目重试旧编辑。
- 写入时保留原文件权限；不允许通过符号链接编辑授权范围外文件。

**MCP Tool 输入 JSON Schema**

```json
{
  "type": "object",
  "properties": {
    "path": {
      "type": "string",
      "minLength": 1,
      "description": "要编辑的已存在 UTF-8 文本文件路径。"
    },
    "edits": {
      "type": "array",
      "minItems": 1,
      "maxItems": 100,
      "description": "按声明顺序执行的精确文本替换列表。",
      "items": {
        "type": "object",
        "properties": {
          "old_text": {
            "type": "string",
            "description": "必须在当前中间内容中匹配的原始文本。"
          },
          "new_text": {
            "type": "string",
            "description": "用于替换 old_text 的新文本；空字符串表示删除。"
          },
          "replace_all": {
            "type": "boolean",
            "default": false,
            "description": "是否替换 old_text 的全部出现位置；省略时为 false。"
          }
        },
        "required": ["old_text", "new_text"],
        "additionalProperties": false
      }
    },
    "expected_sha256": {
      "type": "string",
      "pattern": "^[0-9a-f]{64}$",
      "description": "可选的修改前文件 SHA-256，通常取自最近一次 read_file。"
    }
  },
  "required": ["path", "edits"],
  "additionalProperties": false
}
```

**MCP Tool 输出 JSON Schema**

```json
{
  "type": "object",
  "properties": {
    "path": {
      "type": "string",
      "description": "文件的规范化绝对路径。"

      "type": "boolean",
```

#### `bash`

**MCP Server 返回的 Tool 名称**

```text
bash
```

**Tool 功能描述**

```text
在 PATH 指定的 Task 沙箱目录中通过非交互式 Bash 执行一段 statement，返回 stdout、stderr 和退出状态。PATH 可以是 Task 工作目录相对路径或沙箱内绝对路径，由 FileSystemAdaptor 规范化为绝对路径。每次调用使用独立 shell，不保留 cd、变量、alias 或 shell option。命令受 Task sandbox、文件系统授权、网络策略、审批策略、固定超时和输出上限约束；超时或输出截断会在结果中明确标记。
```

命令成功启动后，即使退出码非 `0` 或执行超时，也返回符合下述 `outputSchema` 的结果；
策略拒绝、Bash 无法启动等未执行情况返回 Tool error。
