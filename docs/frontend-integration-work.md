# Frontend integration implementation record

User-approved specification: this task's implementation request (2026-09-05).

## Requirements
- Electron owns one JSON configuration and an independent conversation-history SQLite database. Save never applies; Apply restarts Backend after busy warning and explicit override. No config hot reload.
- Pet owns one text/voice realtime connection. Text input via Electron IPC. Backend owns Context, Memory and Task. UI history includes accepted user input and delivered say_to_user only. Voice clause enters history only after complete physical playback, then durable Electron write, then ACK. Interrupted clauses never enter history.
- Task UI is read-only title/status; management via Main Agent. Memory is internal only; remove external management APIs/UI. Keep existing visual design and Live2D.
- Fresh AuraBot runtime data; delete authorized old config/databases after enumerating dedicated paths. Never delete source, model assets, shared third-party data.
- Runtime configuration must be usable through the settings page, including Main model, Pi model, speech and workspaces. Unconfigured capabilities do not prevent settings/desktop startup.
- Source edits require clear top-of-file functional documentation. Test behavior and integration; real microphone/provider smoke is required before claiming complete voice verification.

## Fixed contracts
JSON file: `{version:1, revision:number, persona:{...}, backend:{app,chat_model,main_agent,memory,task}, desktop:{...}}`. Backend reads backend section at startup via AURABOT_CONFIG_PATH. Relative built-in resources use absolute paths generated by Electron. Backend missing config uses safe defaults.
Realtime defaults text. token body `{profileId,soul}` remains. `session.ready` does not start microphone. Commands `{type:'text.submit',command_id,text}`, `{type:'voice.start',command_id}`, `{type:'voice.stop',command_id}`. Response `command.ack` with command_id, status accepted/rejected, code on rejection. `user.message` with message_id,text,source text/voice; partial STT stays private until confirmed. `clause.offer` with clause_id,text,mode text/voice. `renderer.ack` retains clause_id,complete; text ACK commits text delivery without pretending PCM playback. UI status `agent.state` with state idle/listening/thinking/speaking. Voice PCM, pause/resume, audio_end/cancel unchanged. Error codes must contain no secrets.
`POST /api/v1/restart/prepare` body `{force:boolean}` returns `{ready:boolean,busy:{tasks:number,memoryWriting:boolean,mainAgent:boolean}}`; no side effects if busy and !force; ready response fences new work before graceful shutdown. Busy checks include unsettled speech, pending invoke/proposals and actual Memory write, not idle timer. Origin restricted as existing token route. Task list query supports ownerProfileId. Readiness returns configRevision and capability status.

四个 Electron 场景：

1. 全新数据启动并渲染 Hiyori；保存不改变 PID，桌面设置应用不重启，Backend 设置应用后 PID 改变；未配置模型的发送失败不生成成功历史。
2. 真实 Python Main Agent 对接本地 SSE 模型夹具；普通模型 content 不进入历史，只有 `say_to_user` 完成交付后入库；忙碌弹窗默认取消且工作继续；确认应用中断在途回复，未交付回复不入库；重启保留记录。
3. 6401 被独立测试 listener 占用时，设置/桌宠可打开并明确报错，不终止该 listener。
4. 在真实 Electron 中加载构建后的 AudioWorklet；静音合成输入产生 320 样本帧，两句合成音频连续完成，等待真实输出时钟越过句末。该项不使用麦克风，不验证真人听感。

独立审查与黑盒过程中还修复了：PCM 超过排队控制消息、迟到回执误投新会话、STT final 被关闭丢弃、异步 transcript 回调逆序、取消被吞掉导致退出卡住、连续 clause 播放与插值、设备输出前提前 ACK、Vue Proxy 无法跨 IPC 克隆，以及未预声明 Pinia Profile 字段导致初始化不可见。HTTPX 补齐 SOCKS 支持；本地回环模型端点直接连接，外部 Provider 保留用户代理设置。
