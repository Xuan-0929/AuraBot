AuraBot Memory Graph · 2026-05-17

当前记忆系统与图结构改进方向

AuraBot 不再接入闭源 Supermemory。下一阶段以本地节点和边为核心：节点保存事实、偏好、事件与提醒，边保存关联、权重、时序和来源，让记忆既能召回，也能解释。

Local-first Node + Edge Temporal Explainable Recall

现在已经有什么

记忆节点 memory_nodes 保存 trait、preference、event、follow_up，并支持 active、stale、completed、archived 状态。
关系边 memory_edges 保存 relates_to、caused_by、scheduled_for、preference_for、opposes 和权重。
有界扩散 召回先选 seed nodes，再沿边做深度和数量受限的 graph traversal，避免上下文膨胀。
调试解释 Memory Debug 能看到 query、planner terms、seed、expanded nodes 和 traversed edges。

当前链路

输入聊天消息、任务结果、提醒请求
→
抽取memoryModel 或受控 deterministic 替身
合并判断新建节点或更新旧节点
→
连边规划偏好、事件、提醒之间的关系
召回query terms、target types、seed node scorer
→
回复图扩散后的上下文进入 ChatModel

当前系统最宝贵的部分是“可控”：模型不能直接写 SQL，也不能随意发明 node id。它只能在 schema 内提出候选，最终由 MemoryService、repository 和 traversal 规则收口。

这个基础比外接闭源服务更适合 AuraBot，因为桌宠提醒、Memory Debug、中文短句召回、用户可解释性和本地可用性都已经在现有架构里。

开源项目带来的启发

项目 看到的模式 AuraBot 应该吸收什么
Graphiti Temporal context graph、entities、facts、episodes、custom ontology。 补 episode provenance，让边具备有效期、状态和来源。
Cognee remember / recall / forget / improve，session memory 后台进入永久图谱。 拆开即时体验和后台图谱整理，补一等 forget 工作流。
Mem0 add/search、filters、hybrid search、embedding 和 graph memory。 用混合检索选择 seed nodes，图扩散负责最终解释。
Letta core memory 和 archival memory 分层，agent 通过工具管理记忆。 保留短期上下文、长期图记忆、摘要/画像三层，但写库必须受控。

改进路线

A. 巩固图结构

  • 给边增加 state、confidence、updated_at。
  • 记录边创建原因和 planner 原始输出。
  • 扩展偏好变化、多人关系、长期提醒评估集。

B. 补来源追溯

  • 新增 memory_episodes。
  • 节点和边都关联原始消息或任务结果。
  • 摘要改为可重建视图。

C. 混合召回

  • 保留中文 keyword scorer。
  • 增加 embedding、BM25 或实体 boosting。
  • 检索只选 seed nodes，图负责扩散。

D. 用户控制

  • 记忆审阅、编辑、归档和删除。
  • forget 同步处理 episode、节点、边、摘要和索引。
  • 支持本地图谱导出和迁移。

近期判断

不要把记忆系统替换成外部服务，也不要把所有内容压成向量 chunk。AuraBot 更需要的是一个可以解释、可以调试、可以被用户掌控的本地图谱。

下一步最小闭环是：边模型增强、episode provenance、更多评估语料和 Memory Debug 第二版。做好这四件事，再决定是否引入 embedding 或更重的图数据库。
