# 后端模块划分 v1

后端采用微服务。每个模块运行一个独立 Python 进程，监听一个固定端口。

## 模块详情

### 1. `frontend-api` — 前端接口服务（端口 8000）

桌面端前端的唯一入口，聚合所有需要暴露给前端的能力。

**职责：**
- HTTP REST：配置面板读写（模型服务商、Live2D模型等）、历史对话查询、待提醒列表查询
- WebSocket：实时推送对话回复、Live2D 情绪/动作控制信号、任务执行状态
- 接收前端发来的打字消息和语音输入，转发给 `chat-agent`

---

### 2. `qq-connector` — QQ 接入服务（端口 8001）

**职责：**
- 通过 OneBot / NapCat 协议与 QQ 保持长连接
- 接收 QQ 私聊消息，转发给 `gate-agent`
- 接收 `chat-agent` 下发的回复，发送给 QQ 用户

---

### 3. `wechat-connector` — 微信接入服务（端口 8002）

**职责：**
- 通过微信协议（如 WeChatPadPro）与微信保持长连接
- 接收微信私聊消息，转发给 `gate-agent`
- 接收 `chat-agent` 下发的回复，发送给微信用户

---

### 4. `gate-agent` — 门控 Agent 服务（端口 8010）

对应 PRD"门控Agent"：判断碎片化消息是否触发主对话。

**职责：**
- 缓冲来自 QQ/微信 的零散消息，判断是否满足唤醒条件（如消息停顿超阈值、明确提问等）
- 检测话题切换：若检测到话题跳转，向 `chat-agent` 发出打断信号，并在新话题上下文中重新触发
- 聚合后的消息以及来源渠道信息，一并推入 `chat-agent` 的处理队列

---

### 5. `chat-agent` — 主对话 Agent 服务（端口 8020）

对应 PRD"主对话Agent"：全生命周期单进程、单 session、串行处理。

**职责：**
- 维护一个全局消息队列，依次处理来自各渠道（QQ/微信/前端/定时任务）的触发
- 持有唯一的长期 session 上下文，伴随应用生命周期
- 构造带 SOUL 语气的回复，断句后推送给对应渠道（`qq-connector` / `wechat-connector` / `frontend-api`）
- 输出情绪和动作控制信号，由 `frontend-api` 转发给前端驱动 Live2D
- 读写 `memory-service`（仅此模块有读写权限）
- 向 `task-agent` 派发任务请求，可查询进度、发出打断指令

---

### 6. `task-agent` — 任务 Agent 服务（端口 8030）

对应 PRD"任务Agent"：处理用户委托的具体任务。

**职责：**
- 接收 `chat-agent` 下发的任务（携带分配的技能组和工具组）
- 每个任务作为独立协程/子线程运行，支持多任务并发
- 暴露进度查询接口和打断接口
- 任务完成后将结果上报 `chat-agent`；执行中途需要信息时，向 `chat-agent` 发问
- 任务完成后，将本次任务中提炼出的可复用步骤写入 `skill-registry`

---

### 7. `memory-service` — 记忆服务（端口 8040）

**职责：**

**短期记忆（内存 + 磁盘持久化）：**
- 维护主对话的滑动上下文窗口
- 进程重启后从磁盘恢复
- 定期将重要片段提交长期记忆写入

**长期记忆（向量数据库 + 磁盘持久化）：**
- 写入时自动从对话记录中提取记忆点
- 查询时返回按置信度排序的记忆表
- 支持选择性遗忘（冲突记忆点可标记删除），无时间衰减权重

**访问控制：**
- 仅接受来自 `chat-agent` 的读写请求，其他服务无权访问

---

### 8. `voice-service` — 语音服务（端口 8050）

**职责：**
- **STT**：接收音频流，转写为文字，返回给 `frontend-api` 或直接触发 `chat-agent`
- **TTS**：接收文字，合成音频；支持流式断句——遇到句末标点（。？！…）即发起合成，降低端到端延迟
- 作为 STT → LLM → TTS 流水线的语音端点

---

### 9. `scheduler-service` — 定时任务服务（端口 8060）

**职责：**
- 管理 **cron 任务**（固定时间，如每天早 8 点问候）和 **倒计时任务**（N 分钟/小时后触发）
- 到时向 `chat-agent` 队列推入触发事件
- 维护"待提醒"列表，供 `frontend-api` 查询展示

---

### 10. `skill-registry` — 技能/工具注册服务（端口 8070）

**职责：**
- 管理 Skill 组（二级目录结构：skill group → skills）
  - 由 `task-agent` 提炼后写入
  - 用户可通过 `frontend-api` 增删改
- 管理 Tool 组（二级目录结构：tool group → tools）
  - 由用户在配置面板配置 MCP 服务器，本服务负责读取并注册
- 暴露查询接口，`chat-agent` 在派发任务前查询可用的技能组和工具组

---

## 进程间通信

| 场景 | 方式 |
|------|------|
| 普通请求/响应（低频） | HTTP REST（FastAPI / aiohttp） |
| 实时推送 / 事件通知 | 内部 HTTP POST 回调，或 Redis Pub/Sub（如引入 Redis） |
| 前端双向通信 | WebSocket（由 `frontend-api` 统一管理） |

初期建议全部走 **HTTP REST**（简单、可调试），等性能瓶颈出现后再迁移高频路径。
