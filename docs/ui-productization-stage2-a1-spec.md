# AuraBot UI Productization Stage 2 Spec

## 1. 目标

本阶段承接 `settings-center-stage1` 之后的产品化工作，但不再讨论信息架构是否成立，而是明确 AuraBot 下一阶段的视觉和交互气质。

这一阶段的目标不是把 AuraBot 做成更强的任务工具，也不是把桌宠只做成一个好看的壳，而是把它稳定推进到下面这个产品判断：

**AuraBot 是一个以陪伴感为第一主体验、以聊天为第一入口、以轻量任务辅助为次要能力的桌面陪伴 AI。**

一句话总结：

**把 AuraBot 从“桌宠优先的可用 MVP”推进到“陪伴感明确、任务不喧宾夺主、界面语言统一的桌面产品”。**

## 2. 阶段定位

这是整体路线中的第二阶段：`UI 产品化`。

当前路线顺序保持不变：

1. 设置页收口
2. UI 产品化
3. 系统通知
4. 桌宠状态机

本 spec 只定义第二阶段。

前一阶段已经解决了：

1. 设置能力分散的问题
2. 设置中心的结构骨架
3. 人格、Live2D 模型、通知承接面的基本入口

这一阶段要解决的是：

1. AuraBot 到底应该让用户先感受到什么
2. 桌宠、聊天、控制台、设置中心是否属于同一种产品人格
3. 任务能力如何保留，但不把 AuraBot 做成一个效率工具

## 3. 核心设计结论

本阶段设计方向锁定为：

- 主视觉方向：`A1 / Daily Cozy`
- 任务存在感方向：`P2 / Sticky Note`

对应的核心结论是：

1. 桌宠主舞台永远是第一视觉中心。
2. 聊天是第一入口，任务是附属信息。
3. 任务只保留“够用的轻量可见度”，不做强面板、不做强指挥台。
4. 设置中心继续使用现有稳定结构，但全部换成 A1 的视觉和文案语言。

## 4. 产品原则

### 4.1 陪伴优先

用户打开 AuraBot 时，第一感受应该是：

- 有一个在场的角色
- 这个角色愿意接住我的状态
- 我可以先说话，不必先管理事情

而不是：

- 我有几个任务在运行
- 今天还有几个待办
- 现在的系统状态是什么

因此，任何会让 AuraBot 更像“仪表盘”“任务工作台”“AI 控制面板”的设计，都不能成为默认主体验。

### 4.2 聊天优先

主线程对话依然是 AuraBot 的第一操作入口。

任务的创建、修改、查询、提醒，本质上都应该像“聊天中顺手发生的事”，而不是要求用户进入单独的任务管理模式。

这意味着：

1. 桌宠气泡和控制台里的文案，要优先像人在说话。
2. 任务信息要被 Aura 包裹后再出现，而不是裸露为系统状态。
3. 任何任务反馈都应优先先回答“对用户意味着什么”，再表达结构化状态。

### 4.3 轻量任务

任务不能消失，但必须退后。

退后的方式不是彻底藏起来，而是：

1. 默认只显示最需要记得的少量事项
2. 尽量以便签、附注、旁白、轻提醒的形式出现
3. 不在主界面常驻复杂状态分层、强进度条、强队列感、强运行感

### 4.4 同一人格

桌宠、控制台、设置中心、通知气泡，必须是同一个 AuraBot，而不是四套不同产品。

这意味着它们需要共享：

1. 相同的视觉材质语言
2. 相同的文案气质
3. 相同的打扰策略
4. 相同的“陪伴先于执行”的行为逻辑

## 5. 视觉语言

### 5.1 整体气质

A1 的视觉方向不是未来感、效率感，也不是游戏化夸张角色舞台，而是：

- 柔和
- 生活化
- 留白多
- 像桌面上的小屋、便签本、纸卡和轻木感物件

应当避免：

- 高对比霓虹科技感
- 强烈的监控面板布局
- 太工程化的卡片密集堆叠
- 过于“移动端效率 App”的标准化界面

### 5.2 色彩

整体色彩以暖白、浅杏、浅米、低饱和棕粉为主。

颜色职责建议如下：

1. 背景：暖白、奶油白、淡米色
2. 次级表面：纸卡感浅杏色
3. 强调色：低饱和奶茶棕、柔和陶土色
4. 文本：暖灰棕，不用纯黑
5. 弱状态：雾面边框、半透明白卡

不要求所有页面同色，但必须都像同一个家族里的材质。

### 5.3 形状与材质

界面组件应偏：

1. 大圆角
2. 较松的内边距
3. 半透明白卡
4. 轻阴影
5. 柔和边框

避免：

1. 锋利分割线
2. 密集小按钮
3. 工具栏感太强的顶部控制区
4. 像 IDE 或 Agent 工作台的模块栅格

### 5.4 排版

排版要强调呼吸感而不是信息填满率。

基本规则：

1. 每个区域只保留一个明确主信息
2. 首屏尽量不出现三层以上的视觉层级
3. 说明文字可以像轻旁白，不要每块都像配置说明
4. 任务信息要比聊天和桌宠气泡更轻、更短、更次级

## 6. 主要界面规范

### 6.1 桌宠主舞台

桌宠窗口是 AuraBot 的默认主视觉壳层。

这个窗口里，视觉优先级必须是：

1. Live2D 角色
2. Aura 当前的陪伴气泡或轻互动
3. 极少量辅助信息
4. 任务便签

桌宠舞台应具备以下特征：

1. 角色始终处于视觉中心区
2. 气泡像自然说话，而不是系统 toast
3. 背景允许有柔和氛围元素，但不能喧宾夺主
4. 快捷操作数量要少，且视觉上尽量轻

桌宠窗口不应出现：

1. 常驻任务列表
2. 指标卡
3. 运行中任务计数面板
4. 强状态条
5. 大块设置入口

### 6.2 控制台

控制台仍然承担完整对话能力，但视觉定位要从“工作台”变成“更安静的聊天室”。

控制台的第一属性是：

- 对话展开面

不是：

- 任务指挥面
- 调试控制台
- Agent 操作台

控制台应具有以下特征：

1. 消息区是主角
2. 输入框清晰但不过于机械
3. 任务信息作为侧边小便签或附属卡片存在
4. 窗口整体比桌宠更完整，但仍保留 A1 的柔和气质

控制台不应默认呈现：

1. 复杂双栏任务面板
2. 高密度状态汇总
3. 大面积技术状态区
4. 强控制感的 action rail

### 6.3 任务的 P2 形态

P2 的结论是：任务默认以“便签式轻任务”出现。

具体要求：

1. 默认只展示 1 到 3 条最需要记得的事
2. 展示内容优先是自然语言摘要，而不是任务 ID 或内部状态
3. 便签应该像陪伴界面上的附属提醒，不像业务面板
4. 便签可以出现在桌宠舞台边缘或控制台侧边，但不能占据主布局中心

任务便签的优先展示内容：

1. 现在最该记得的一件事
2. 今天还有什么别忘了
3. 稍后我会再提醒你什么

任务便签默认不强调：

1. 队列长度
2. 运行中数量
3. 复杂状态分层
4. 执行器信息
5. 明显的系统进度感

### 6.4 设置中心

设置中心沿用 Stage 1 已经建立的结构：

1. `通用`
2. `桌宠行为`
3. `模型`
4. `人格`
5. `Live2D 模型`
6. `通知`

这一阶段不改结构，只改产品语言和视觉表达。

设置中心应从“后台设置页”变成“温柔的角色设置小屋”。

具体要求：

1. 卡片和区块更大、更松、更柔和
2. 首屏摘要更像旁白，而不是纯技术描述
3. 人格页优先展示轻编辑内容
4. Live2D 模型页优先强调当前角色和本机模型切换
5. 通知页强调“我什么时候可以轻轻提醒你”

设置中心里，模型配置仍会保留技术信息，但视觉上要被包进产品语境，避免整页突然变成工程后台。

### 6.5 通知与气泡

桌宠气泡、主动提醒、任务提醒、通知页描述，必须共享同一种说话方式：

1. 先以陪伴式口吻开头
2. 再点明要紧的事
3. 不用硬广播语气

例如目标应接近：

- 我来提醒你一下，刚才那件事差不多到时间了。
- 你前面交代我的那件事，我先帮你记在旁边了。

而不是：

- 任务已到期。
- 事件提醒已触发。
- 任务执行完成。

## 7. 交互原则

### 7.1 默认轻打扰

AuraBot 默认应该是低打扰的。

体现方式：

1. 主界面同时出现的信息少
2. 提示更轻
3. 不抢焦点
4. 不堆状态

### 7.2 渐进展开

先给用户最轻的一层，再按需展开。

层级顺序建议：

1. 桌宠在场
2. 气泡回应
3. 小便签任务
4. 控制台完整聊天
5. 设置中心和高级能力

这条顺序很关键，因为它决定了 AuraBot 不会一上来就像工具。

### 7.3 聊天包裹任务

所有任务相关体验都应被聊天包裹，而不是反过来。

意味着：

1. 用户先说话
2. Aura 理解意图
3. 如果需要，Aura 把事情收成便签或提醒
4. 用户只有在想深看时才进入更完整的控制台

### 7.4 设置不是后台，是关系调教

尤其是 `人格`、`桌宠行为`、`通知` 这三页，不该给用户“配系统”的感觉，而应该更像“和 Aura 商量她怎么陪我”。

这不等于丢掉能力，而是要换一种呈现语言。

## 8. 内容与文案规范

### 8.1 文案气质

文案要满足以下四点：

1. 先像人在说话
2. 先回答用户感受
3. 再表达状态
4. 语气轻，不卖萌过头，也不播报过硬

### 8.2 任务文案

任务文案要从“系统状态”改成“陪伴式提示”。

优先形式：

1. 我先帮你记在旁边了。
2. 这件事我晚点再提醒你。
3. 现在最要紧的是这一个。

避免形式：

1. 当前存在 3 个运行中任务
2. 任务状态已更新
3. 执行器不可用

技术错误和模型错误仍然需要清楚表达，但应尽量用产品语气包裹。

### 8.3 设置文案

设置页标题、说明、帮助文案，应尽量使用用户视角语言。

例如：

- “Aura 平时怎么陪你”
- “什么时候可以提醒你一下”
- “现在在用哪个模型”

而不是把所有标题都写成技术字段名。

## 9. 范围边界

### 9.1 In Scope

本阶段要完成：

1. 桌宠窗口整体视觉产品化
2. 控制台整体视觉产品化
3. 任务从面板感收束为 P2 便签式轻任务
4. 设置中心的视觉语言统一
5. 任务、气泡、提醒、设置说明的文案气质统一
6. 一套完整的 A1 视觉系统基础变量和组件风格

### 9.2 Out of Scope

本阶段明确不做：

1. 系统通知能力本身的完整交付
2. 桌宠复杂状态机和分时段状态调度
3. Live2D 动作映射编辑器
4. 高级通知编排器
5. 全量任务系统机制重写
6. 记忆系统能力重写

## 10. 对现有实现的约束

本 spec 必须兼容当前已经成立的产品骨架：

1. Live2D 桌宠窗口仍是默认入口
2. 控制台仍是完整主聊天线程展开面
3. 设置中心仍是独立窗口
4. 现有模型设置、人格设置、Live2D 模型页、通知页结构继续保留
5. 任务能力仍可用，但视觉上不再做强存在感

因此，本阶段默认以“重做产品表达”而不是“重写核心架构”为主。

## 11. 设计落地建议

建议按下面顺序实现：

1. 先建立 A1 全局视觉变量和基础组件样式
2. 先改桌宠窗口的视觉层级和轻任务便签
3. 再改控制台，让消息成为主角、任务退到附属位
4. 再统一设置中心的卡片、说明和页面气质
5. 最后统一任务播报、提醒、设置说明等用户可见文案

这样做的原因是：

1. 桌宠是第一主视觉，必须先定
2. 控制台是第二体验层，必须跟上主气质
3. 设置页已经结构稳定，适合最后统一翻译成新视觉语言

## 12. 风险与防偏移

本阶段最容易出现的偏移有三种：

### 12.1 偏回工具产品

表现：

- 任务面板重新变大
- 状态卡越来越多
- 控制台越来越像工作台

避免方式：

- 默认只做便签式任务
- 先审“用户第一眼看到什么”，再审功能是否齐

### 12.2 只有好看，没有可用性

表现：

- 陪伴感很好，但任务入口太难找
- 设置页太软，真实配置变得难理解

避免方式：

- 保留 P2 便签作为稳定轻入口
- 保留设置页的结构稳定性，不推翻信息架构

### 12.3 视觉统一了，文案没统一

表现：

- 页面变柔和了
- 但任务播报、提醒、错误消息还像系统广播

避免方式：

- 把用户可见文本一起纳入本阶段范围
- 对聊天、任务、提醒、设置说明做统一语气收口

## 13. 验收标准

本阶段完成时，应满足以下判断：

1. 用户打开 AuraBot，第一感觉是被一个在场的角色陪着，而不是进入任务系统。
2. 用户能自然聊天，不需要先理解任务结构。
3. 任务依然可见可用，但默认只像一张轻便签，不像任务面板。
4. 控制台更像安静聊天室，而不是 Agent 工作台。
5. 设置中心虽然仍包含技术配置，但整体已属于同一产品气质。
6. 桌宠气泡、提醒、任务反馈和设置说明的说话方式明显更统一。
7. 整体 UI 让 AuraBot 更像“陪伴型桌面产品”，而不是“带 Live2D 外壳的 AI 工具”。

## 14. 验证建议

本阶段完成后，至少应进行以下验证：

1. 人工走查桌宠窗口、控制台、设置中心三大界面，确认第一视觉中心是否仍是陪伴体验。
2. 人工验证任务创建、任务提醒、任务完成播报在视觉上是否仍保持轻量附属位。
3. 人工验证人格页、Live2D 模型页、通知页和模型页是否都已经切到 A1 语言。
4. 对任务完成、主动提醒、普通聊天回复、错误提示进行文案抽查，确认没有明显系统广播腔。
5. 至少补一个从桌宠到控制台再到设置中心的 e2e 视线路径，验证产品气质没有因为窗口切换而断裂。
