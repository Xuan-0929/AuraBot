控制台聊天输入栏的四种附件按钮

这几版都假设保留当前控制台的深色玻璃风格。核心差别是：附件入口有多显眼、会不会挤占输入空间、用户是否能一眼理解“可以拖文件/图片进来”。

A. 左侧独立图标

把附件入口放在输入框左侧，像聊天软件的标准形态。

文件气泡改进方案

更小、更稳、不重叠的附件 chip

下面四版都修掉长文件名重叠问题：核心是让文件名放进 minmax(0, 1fr) 的截断容器里，并用 overflow: hidden、text-overflow: ellipsis、white-space: nowrap 保证不会压到关闭按钮。

1. 超紧凑胶囊

高度 28px，适合当前 A 版输入栏，视觉负担最小。

推荐
very-long-product-requirements-document-final-v12.pdf× flow.png×
适合：聊天输入栏常驻显示，省空间。 代价：文件类型和大小信息弱一点。

2. 两行信息卡

第一行文件名，第二行类型/大小；不高，但信息更完整。

信息清楚
very-long-product-requirements-document-final-v12.pdfPDF · 2.4 MB× screenshots-for-debugging-this-specific-task.png图片 · 684 KB×
适合：用户经常上传多种类型文件，需要看到大小。 代价：比胶囊高，输入栏会更占空间。

3. 图标 + 长条

更像“附件列表”的一项，长文件名更稳。

最稳
PDFvery-long-product-requirements-document-final-v12.pdf× IMGscreenshots-for-debugging-this-specific-task.png×
适合：文件名经常很长，想最大程度避免挤压。 代价：比普通 chip 更像列表，存在感更强。

4. 单行附件栏

附件独占一整行，文件名左侧截断，右侧保留类型/大小。

批量友好
very-long-product-requirements-document-final-v12.pdfPDF · 2.4 MB × screenshots-for-debugging-this-specific-task.png图片 · 684 KB ×
适合：一次上传多个文件，列表最整齐。 代价：最占高度，不如胶囊轻。
