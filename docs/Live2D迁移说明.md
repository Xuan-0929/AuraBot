# AIRI UI 迁移接入方案

以下称“Live2D解析界面”为“前端”。

## 1. 迁移总原则

### 只搬 UI，不搬 AIRI 业务内核

AuraBot 继续保留自己的：

1. Agent Harness
2. 设置界面

迁移的对象仅限于：

- 渲染live2D模型的框
- 预留好的“动作接口”，驱动live2D模型的动作，表情等等。

**甚至`stt->Agent->tts`的流水线也是自己实现，不搬AIRI的**

我们在项目的`src/renderer/`中适配前端。


## 2. 迁移技术栈

- Electron
- ts + vue
- 其他依然照搬Airi的技术栈。

## 3. Live2D解析界面需求分析

- 交互：
    - Live2D人偶始终看相用户的鼠标指针
- UI设计：
    - Canvas上除了Live2D人偶和几个按钮外，其他部分都是透明的。
    - Electron canvas只占页面的一小部分。
    - 当用户鼠标悬停在Live2D人偶上时，人偶会变成半透明，露出底下的页面。
    - 用户的鼠标可以点穿canvas到canvas窗口后面的内容（除了canvas上的几个按钮）。
    - 用户的鼠标移动到canvas上时，canvas的边框会描一圈橙色。
    - 用户可以拖动canvas的边框缩放canvas的大小
    - 按键固定存在于canvas右下角，从上到下依次是：
        - 打开控制台(控制台已经实现)
        - 打开语音输入输出（预留好给语音模块使用的接口）
        - 按住拖拽（用户按住该按钮，通过拖拽可移动canvas窗口的位置）
- 功能：
    - Live2D人偶会依据对话中传递的信号做出相应的表情和动作等
    - 要高清显示人偶，不要为了节约性能而压缩分辨率。


## 预留接口

- 维护一个动作缓冲区，接收其他模块的“展示动作”申请，依次加载动作到Live2D人偶上。同时，返回动作展示是否成功（在入队前，就判断是否匹配Live2D模型预制好的动作）。

- 代码间封装结构良好，符合OOP理念，方面接入后续可能的新功能需求。
